# اسپرینت ۱ — تثبیت پایه کافه یار ۳۶۰

## ورودی و معیار پذیرش

ورودی فقط `cafe-nima-github-ready.zip` بود؛ در checkout مستقل نگهداری و ابتدا بدون تغییر در Git ثبت شد. `AGENTS.md` مطالعه شد. Python/FastAPI، SQLite، رابط RTL، endpointها و بات مستقل حفظ شدند. هدف اسپرینت: رفع چند خطای قابل بازتولید، تحویل ابزار عملیاتی محلی و افزایش پوشش تست؛ تکمیل همه دامنه محصول در این اسپرینت ادعا نمی‌شود.

مبنای تست: ۹ تست موجود موفق. نسخه تحویلی: ۲۲ تست موفق روی Linux/Python 3.12؛ یک هشدار deprecation در TestClient. وابستگی‌های Python و ابزار اختیاری Playwright قفل شدند. CI چهار ترکیب Ubuntu/Windows و Python 3.11/3.12 را تعریف می‌کند؛ اجرای واقعی آن به انتشار GitHub وابسته است.

## تغییرات واقعی و آزموده‌شده

| تشخیص رمز عمومی در DB قدیمی | startup غیرنمایشی رد می‌شود؛ ابزار password رمز را تغییر و نشست‌ها را باطل می‌کند |
| snapshot مصرف سفارش | حذف شات اضافه، ویرایش رسپی و restart بر مصرف ۷۲ گرم قهوه و ۴۴۰ml شیر سفارش آزمایشی اثر ندارد |
| مهاجرت افزایشی | ارتقای schema قدیمی ID، token و مبلغ سفارش را حفظ و مواد را فقط یک‌بار ثابت می‌کند |
| حفظ رسپی سفارشی پس از restart | حذف یک جزء شیر گیاهی پس از startup دوباره درج نمی‌شود |

| تردد با نقش محدود | کارمند فقط حساب/تردد خودش؛ مدیر همه؛ خروج اولیه بدون ورود رد می‌شود |

| جلوگیری از ثبت تلگرام غیرمجاز | کاربر متصل‌نشده و کد منقضی هیچ ترددی درج نمی‌کنند؛ شبکه mock است |

فرانت‌اند از صف‌های جدید استفاده می‌کند. ورود سریع دمو فقط در حالت دمو نمایش داده می‌شود و صفحه presentation در حالت غیرنمایشی حساب‌های دمو نمایش نمی‌دهد. آمار دریافتی صفحه صندوق همچنان به تاریخچه ۱۰۰ سفارش اخیر محدود است و برچسب آن اصلاح شده؛ جایگزین گزارش کامل روز نیست.

## مرورگر و اجرای محلی

سرور واقعی uvicorn روی loopback اجرا و با Chromium headless آزمایش شد:

- منوی میز ۳ → افزودن محصول → ثبت سفارش و نمایش رهگیری.
- ورود باریستا → پذیرش → آماده‌سازی → آماده تحویل → تحویل.
- ورود صندوق‌دار در context مجزا → ثبت پرداخت نقدی دستی.
- عرض ۳۹۰ پیکسل: اسکرول افقی نبود؛ خطای pageerror ثبت نشد.
- حالت غیرنمایشی: میان‌برهای ورود دمو و رمزهای presentation در مرورگر پنهان بودند.
- تصاویر جدید در `docs/screenshots/sprint1-*` ثبت شدند؛ سایر تصاویر از بسته اولیه‌اند.

دستور بازاجرای smoke اختیاری (نیازمند Node.js؛ runtime محصول همچنان Python است):

```bash
npm ci
npx playwright install chromium
```

در ترمینال اول، با یک مسیر DB آزمایشی تازه:

```bash
DEMO_MODE=1 CAFE_DB_PATH=/tmp/cafeyar-browser.sqlite3 python -m uvicorn app:app --host 127.0.0.1 --port 8010
```

در ترمینال دوم `npm run test:browser` را اجرا کنید. اسکریپت سفارش و پرداخت ساختگی ایجاد می‌کند؛ فقط روی DB آزمایشی اجرا شود. اسکرین‌شات‌ها در `test-artifacts/` هستند و commit نمی‌شوند. برای Chromium ازقبل نصب‌شده می‌توان `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` را تنظیم کرد. تست ویندوز و اتصال زنده تلگرام در محیط حاضر انجام نشده‌اند.

## Git و انتشار

یک commit مبنا و commit اسپرینت در Git محلی ایجاد شدند. فایل DB، بکاپ، `.env`، توکن واقعی و node_modules در نسخه‌بندی نیستند. ساخت مخزن با مجوز اتصال فعلی از سوی GitHub با `Resource not accessible by integration (createRepository)` رد شد؛ push و Actions انجام نشده‌اند. اقدام دقیق مدیر فنی در `GITHUB-SETUP-FA.md` آمده است. bundle مستقل برای انتقال تاریخچه و ZIP سورس قابل انتقال تهیه می‌شود.

## ریسک و rollback

- پیش‌فرض مستقیم برنامه اکنون DEMO_MODE=0 است؛ برای نمایش، راه‌اندازها عمداً DEMO_MODE=1 می‌گذارند. این تغییر رفتار مستند و تست شده است.
- مصرف سفارش قدیمی از رسپی موجود در لحظه مهاجرت گرفته می‌شود؛ رسپی تاریخی قبلاً حذف‌شده قابل بازیابی نیست. برای سفارش جدید مقدار مواد در ثبت سفارش ثابت و هزینه واحد در تحویل خوانده می‌شود.
- سفارش قدیمی hash درخواست ندارد؛ retry کلید قدیمی ۴۰۹ می‌گیرد. ابتدا رسید قبلی بررسی شود و با حدس کلید جدید سفارش مجدد ایجاد نشود.
- صف‌های active/unpaid همه اقلام باز را برمی‌گردانند؛ برای حجم خیلی بالا به pagination عملیاتی و شاخص‌های بیشتر نیاز است.
- قبل از ارتقا با `manage.py backup` بکاپ بگیرید. برای rollback، وب و بات را متوقف، نسخه کد قبل را در checkout جدا بازیابی و از backup در **مسیر DB جدا** استفاده کنید. DB فعال را overwrite یا migration را با DROP در محیط واقعی معکوس نکنید.

## اولویت اسپرینت‌های بعد

۱. مالی و صندوق: تفکیک دریافتی از فروش تحقق‌یافته و مطالبات؛ گزارش روز/ماه و بازه؛ رسید و چاپ؛ مغایرت، اصلاح و استرداد با عامل/دلیل و شیفت صندوق. مشکل فعلی سودِ تسویه پیش از تحویل هنوز رفع نشده است.

۲. ایمنی و عملیات: محدودیت تلاش ورود، CSRF و HTTPS، کاربر فعال/غیرفعال و مدیریت میز، سیاست رزرو موجودی، جلوگیری از دوبارکلیک و بازیابی سبد پس از قطع پاسخ، محدودیت مقادیر بسیار بزرگ و بارسنجی SQLite. غیرفعال‌کردن کارمند و ابطال اتصال بات هنوز کامل نیست.

۳. CRM و تردد: تاریخچه تفصیلی و دسته‌بندی وفاداری، جلوگیری از overwrite نام پرونده با شماره تأییدنشده، تعریف مراجعه موفق؛ گزارش ساعت کار و شیفت و اصلاح ممیزی‌شده، offset/inbox پایدار بات. تعداد مراجعه فعلی سفارش لغوشده را نیز شامل می‌شود.

۴. پایلوت: backup خودکار و تمرین بازیابی، مانیتورینگ و log امن، آزمون Windows/LAN با گوشی واقعی و گزارش محدودیت‌های استقرار. معماری فعلی حفظ و لایه‌ها تدریجی استخراج شوند؛ تصمیم PostgreSQL پس از اندازه‌گیری نیاز گرفته شود.

پرداخت آنلاین و اتصال مستقیم سخت‌افزار POS خارج از محدوده‌اند. API پولی یا AI خارجی اضافه نشده است.
