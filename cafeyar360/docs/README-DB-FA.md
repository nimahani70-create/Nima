# دیتابیس کافه یار ۳۶۰

SQLite در Git قرار نمی‌گیرد. با `DEMO_MODE=1` و `python manage.py init` دیتابیس نمونه ساختگی ایجاد کنید. در حالت غیرنمایشی، سه متغیر رمز قوی لازم است و داده نمونه درج نمی‌شود. `.env` خودکار خوانده نمی‌شود. `docs/schema.sql` فقط ساختار بدون داده است.

ارتقا افزایشی در startup یا init انجام می‌شود؛ پیش از ارتقا `python manage.py backup backups/before-upgrade.sqlite3` اجرا کنید. بکاپ شامل داده خصوصی است و باید خارج از Git بماند. برای بازیابی، سرویس وب و بات متوقف و بکاپ در مسیر تازه قرار داده شود. راهنمای کامل در [README](../README.md) و [ریسک مهاجرت](SPRINT-01-FA.md) آمده است.

نسخه ۱.۴: migration افزایشی schema v3، پول canonical در ستون‌های *_minor با واحد یک‌صدم تومان، شیفت/استرداد/درخواست و گردش نقد. جزئیات محدودیت دقت و rollback در گزارش اسپرینت دوم است. سوابق قدیمی شیفت ساختگی نمی‌گیرند. نام فایل DB همچنان cafe_nima.sqlite3 است.

نامزد ۱.۴.۱ هیچ رمز ثابت اجرایی ندارد. برای DB تازه، manage.py init رمزها را مخفی می‌پرسد یا از محیط می‌خواند. DB نمونه review فقط hashهای تصادفی ساختگی دارد؛ پیش از استفاده روی کپی محلی با manage.py password برای هر حساب رمز خودتان را تعیین کنید. ابزار مدیریت قبل از init روی DB موجود یا تغییر رمز، snapshot جدید در پوشه ignored backups می‌سازد. رمزها در فایل همراه یا گزارش ذخیره نمی‌شوند.
